## 2. 真正要学的五环，而不是增加九种业务

**免费触达 → 自动保留游客身份 → 完成一件事 → 愿意再来 → 自愿绑定邮箱找回记录 → 在交付明确时付费。**

- 免费触达：月老首页「免费求签」「8 题情感测验」「今日心笺」无需登录。SEO 和分享流量可落到对应结果/工具，入口不必先跳登录。
- 完成一件事：每个入口要给出完整且看得懂的免费结果；用户先获得收获，不能抽到一半弹充值墙。
- 愿意再来：每日心笺和 7 日签到适合低频、轻量回访。不要把感情问题制造成每日焦虑检查，也不要强推通知。
- 需要保存时登录：只有当用户点击「我的」「查看已购权益」「保存未来会同步的个人记录」或下单时，才说明登录的实际价值。目前账号只读已购记录；**不要声称免费签到或自由心事已跨设备同步**。
- 付费服务：用户理解「免费签文」与「额外深度解读」的区别、价格/币种/退款后再结算。尚无完整 AI 履约与真实 Stripe 测试时绝不开放收费。

### 账号思路的重要修正（11 月 9 日）

用户指出菩提苑可能会在首次访问时自动分配账号、由用户之后绑定联系方式。其公开「更多」页面确实提供「用吉祥号或手机号在新设备恢复」，但动态登录后台不可核实，不能声称其技术栈已确认。月老应按**先游客身份，再自愿绑定邮箱**设计：使用 Supabase 匿名用户并在同一用户 ID 上升级，而不是先要求邮箱 OTP。详见 [游客优先账户方案](./GUEST_FIRST_ACCOUNT_MODEL_2026-11-09.md)。当前 PR 的邮箱登录代码仍是旧流程准备，不是已实现的游客绑定；不得合并后宣称符合此模式。

## 4. 优先级及验收标准（不是虚构已完成）

### P0 安全上线闭环

1. Cloudflare 正确账户部署（禁止用户 VPS）；确认 Live/preview Worker 和环境隔离。
2. 自有发信域+Supabase Auth 6 位 OTP 模板+Turnstile+限流，通过真实邮箱发信、验证、退出和刷新测试。
3. 保持免费入口可用，匿名不能读取账户/购买权益；禁用充值与 AI 即时聊天。
4. Stripe 测试模式使用**独立测试数据库**，验收退款/重复回调/权益撤销，再决定付费服务上线条件。

### P1 用户回访与记录

1. 「我的姻缘簿」分为 **已购/已解锁、历史记录（未来可用）、设置/隐私**，其中未开发功能不显示假数字或空按钮。
2. 保留每日心笺和签到；登录后同步需单独实现明示同意、导入、删除；未实现前仅本机。
3. 免费求签结果提供明确的「再求一支」「每日心笺」路径，非强制升级。
4. 不同关系情境提供不同文案，但不凭签文声称能读取第三方真实心意。

### P2 自然增长（待产品稳定后）

1. 结果页可选分享**只有签号/诗意/公开解读**的卡片，绝不默认带入私人提问或邮箱。
2. 研究开放图、页面标题与落地页自然搜索入口；衡量分享点击与免费体验完成，而非靠强制邀人得奖励。
3. 参考站的多师父角色、功德积分、收费供灯、分享返佣并不适合直接复制到月老。先验证真实需求和伦理/法律风险。

## 5. 建议监测的真实指标（待埋点后才能计算）

- 免费入口点击 → 求签/测验完成率
- 下一日再次打开每日心笺的用户比例（在隐私允许的范围内）
- 登录入口点击 → OTP 发送成功 → OTP 验证通过
- 登录后访问「我的姻缘簿」和已购内容的成功率
- Stripe 测试付款成功 → Webhook → 权益交付时间、失败与退款撤销
- 投诉、退款、邮件退信和登录限流触发情况

**不以每日活跃或付费转化为由向用户制造焦虑。** 不借人物、长老或典籍引用暗示真人坐堂/认证、也不以算命替代现实决定；清晰标注 AI 生成与文化反思性质。
